# 第 5 章 監督式微調（SFT）— 精簡說明

> 來源：`287_PDFsam_LLM Engineer's Handbook - Paul Iusztin, Maxime Labonne.pdf`，第 5 章。
> 寫作規則：類 ASD-STE100。一句只說一件事。每句不超過 20 個字。用簡單動詞。

## 1. 目的

- SFT 把基座模型變成助理。
- 基座模型只會預測下一個詞。
- SFT 用「指令—答案」配對訓練它。
- 結果：模型會聽指令，且具備領域知識。

## 2. 名詞定義

| 名詞 | 白話解釋 |
|---|---|
| 指令（Instruction） | 給模型的輸入。 |
| 答案（Output） | 模型應輸出的回覆。 |
| 系統提示（System） | 全域行為規則。 |
| 對話模板 | system、user、assistant 的固定格式。 |
| Alpaca 格式 | 欄位：`instruction`、`input`（可省略）、`output`。 |
| ShareGPT / OpenAI 格式 | 訊息清單，可做多輪對話。 |

## 3. 資料品質準則

好的樣本有三個特性：

1. 正確 — 答案無誤，且對應指令。
2. 多樣 — 涵蓋主題、長度、文體。
3. 困難 — 包含多步驟推理難題。

數量指引：

- 通用助理：目標 1,000,000 筆。
- 單一任務（翻譯、摘要）：100–100,000 筆。
- 大模型（約 70B）：1,000 筆高品質樣本即可見效。
- 小模型（約 7B）：需更多樣本學習對話格式。

## 4. 流程 A — 製作指令資料集

依序執行。不可跳過步驟 5。

1. 蒐集原始文本（第三章爬取之文章）。
2. 清洗每篇文章（刪雜字、修空格）。
3. 切成 1000–2000 字區塊。
4. 每區塊用 LLM 產生 5 組指令—答案。
5. 指令須自足（禁用「上下文」、「原文」、「系統」等詞）。
6. 答案須模仿原作者文風。
7. 輸出用 JSON 模式（免手動解析）。
8. 切分：90% 訓練，10% 測試。
9. 上傳至 Hugging Face Hub。
10. 開啟資料集檢視器，人工抽查樣本。

範例成果：3,335 組 → `mlabonne/llmtwin`。

## 5. 流程 B — 清洗資料

依序執行：

1. 規則過濾 — 刪過短答案。刪過長答案。刪含禁用詞樣本。檢查程式碼與 JSON 語法。
2. 去重 — 雜湊（MD5/SHA-256）刪完全重複。MinHash + Jaccard 刪近似重複。向量 + 餘弦相似度刪同義重複。
3. 去污染 — 刪除與測試集相同的訓練樣本。將測試集加入去重輸入，僅保留測試副本。
4. 品質評分 — 可選：LLM 評分（1–4 分）、獎勵模型、小型分類器。用 2–3 個評審降低偏誤。隨機調換答案順序（修正位置偏誤）。

## 6. 流程 C — 增加資料

- 生成：從 5–10 個種子提示出發，請 LLM 產新配對。
- 演化（Evol-Instruct）：
  - 縱向 = 加難原指令（加限制、加推理步驟）。
  - 橫向 = 同領域產新的稀有指令。
- 回饋（UltraFeedback）：產多個答案，評分，僅留最佳。

警告：合成資料會複製模型偏誤。生成後務必重做流程 B。

## 7. 何時微調

1. 先試提示工程（少樣本、RAG）。
2. 量測準確率、成本、延遲。
3. 未達標，才蒐集指令資料。
4. 資料充足（>1000 筆好樣本），才啟動 SFT。

限制：

- SFT 教不了全新的知識，可能產生幻覺。
- SFT 可能抹除舊知識（災難性遺忘）。

## 8. 方法選擇表

| 方法 | 做法 | 記憶體 | 品質 | 適用時機 |
|---|---|---|---|---|
| 全量微調 | 訓練全部參數 | 約 16 bytes/參數（7B 需 112 GB） | 最高 | 有多卡伺服器 |
| LoRA | 只訓練小型適配器（rank 8–64） | 低 | 接近全量 | 只有單卡，要品質 |
| QLoRA | LoRA + 4 位元凍結權重 | 最低 | 略低 | 視訊記憶體不足 |

書中範例：Llama 3.1 8B + LoRA r=32、alpha=32，目標為全部線性層。

## 9. 流程 D — 微調（書中範例）

工具：`TRL (SFTTrainer)` + `Unsloth (FastLanguageModel)`。

1. 登入 Hugging Face（`.env` 填 `HF_TOKEN`）。
2. 載入基座模型 `meta-llama/Meta-Llama-3.1-8B`，`max_seq_length=2048`，`load_in_4bit=False`（用 LoRA）。
3. 掛載 LoRA（`r=32`，`lora_alpha=32`，`dropout=0`）。
4. 載入 `mlabonne/llmtwin` + `mlabonne/FineTome-Alpaca-100k` 前 10,000 筆，合併。
5. 套用 Alpaca 模板，每筆結尾加 EOS 符號。
6. 切分 95% 訓練 / 5% 測試。
7. 訓練：`lr=3e-4`，`linear` 排程，`epochs=3`，`batch=2`，`accum=8`（等效 16），`optim=adamw_8bit`，`weight_decay=0.01`，`packing=True`。
8. 用 Comet ML 監控：損失須下降；驗證損失不可上升；梯度範數須穩定。
9. 用 `FastLanguageModel.for_inference()` 測一句提示。
10. 存合併模型（`merged_16bit`）並上傳至 Hub。

時間參考：A100 上約 50 分鐘。

關鍵超參數：

- 學習率：2e-5–5e-4（LoRA 用 1e-4–3e-4；全量用 1e-5–5e-5）。
- 上下文長：短任務用 2048–4096。
- 訓練輪數：大資料用 1–3；小資料用 3–5。驗證損失上升即停。
- 優化器：預設 `adamw_8bit`。記憶體不足改 `adafactor`。

## 10. 訓練後檢查

- [ ] 答案在 EOS 停止（無無限生成）。
- [ ] 模板符號完全正確（一格空格錯誤即失敗）。
- [ ] 訓練損失分三段下降（對應 3 輪）。
- [ ] 驗證損失未持續上升（上升即過擬合）。

## 11. 一頁總覽

原始文章 → 清洗 → 切塊 → LLM 產配對 → 過濾 → 去重 → 去污染 → 評分 → 混入通用資料 → 套模板 → LoRA 訓練 → 測試 → 存檔。

遵守一條規則：品質重於數量。
