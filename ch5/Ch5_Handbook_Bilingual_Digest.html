1Chapter Overview 章節導覽

EN SUMMARY After pre-training, Supervised Fine-Tuning (SFT) refines an LLM with curated instruction–answer pairs. It serves two purposes: teaching the model a specific chat format so it behaves as a conversational agent, and adapting its broad knowledge to targeted tasks or domains. SFT bridges the gap between general language understanding and practical utility — improving instruction-following, relevance, and coherence for goals like summarization, translation, or domain expertise. The chapter covers three topics: creating a high-quality instruction dataset, SFT techniques, and implementing fine-tuning in practice.
繁體對照 預訓練之後，監督式微調（SFT）用精心策展的「指令—答案」配對來精修 LLM。目的有二：教模型學會特定聊天格式、成為對話代理；並把廣泛知識調校到特定任務或領域。SFT 彌補了「通用語言理解」與「實用性」之間的落差——提升聽指令能力、回覆相關性與連貫性（如摘要、翻譯或領域專業）。本章涵蓋三個主題：建立高品質指令資料集、SFT 技術、實際動手微調。

2Creating an Instruction Dataset 建立指令資料集

EN SUMMARY Building the instruction dataset is usually the hardest part of fine-tuning. Raw text rarely contains natural instruction–answer pairs, so it must be transformed into a format with both parts. Quality matters as much as quantity: substantial time goes into manually checking and verifying individual samples to keep the dataset accurate and useful for training.
繁體對照 建立指令資料集通常是微調流程中最難的部分。原始文本很少有現成的「指令—答案」自然配對，必須轉換成同時含兩者的格式。品質與數量同樣重要：需要投入大量時間人工抽查、逐一驗證樣本，確保資料集正確且對訓練有用。

2.1 Data quantity 資料數量

EN SUMMARY More high-quality samples generally help, but noisy or hallucinated data quickly degrades the model — quality beats raw size. A practical recipe is to start with a small curated set (around 1,000 samples), evaluate, then scale up. In the book's example, an LLM (GPT-4o mini) generates on the order of a few thousand pairs (≈3.3k for the llmtwin dataset) from the crawled articles.
繁體對照 高品質樣本越多通常越好，但雜訊或幻覺資料會很快污染模型——品質比數量重要。務實做法：先建立約 1,000 筆的小型精選集，評估後再擴大。書中範例以 LLM（GPT-4o mini）從爬取文章產出數千組配對（llmtwin 資料集約 3.3k 筆）。

2.2 Data curation 資料策展

EN SUMMARY Curation runs the generated pairs through four quality gates:
  • Rule-based filtering — cheap checks first: remove samples whose answers are too short/long, contain banned words, or whose code/JSON fails syntax checks; drop "instructions" that look like prompts.
  • Deduplication — three layers: exact duplicates via hashing (MD5/SHA-256), near-duplicates via MinHash + Jaccard similarity, semantic duplicates via embeddings + cosine similarity.
  • Decontamination — add the test set to the deduplication inputs; any training sample matching a test sample is removed so the test set stays exclusive.
  • Quality evaluation — an LLM judge scores samples (e.g. 1–4) with structured feedback; using several judges and randomizing answer order reduces bias.
繁體對照 策展把產出的配對過四道品質關卡：
  • 規則過濾——先跑最便宜的檢查：刪掉答案過短／過長、含禁用詞、程式碼或 JSON 語法錯誤的樣本；「指令」長得像提示詞的也刪。
  • 去重——三層：雜湊（MD5/SHA-256）刪完全重複；MinHash＋Jaccard 刪近似重複；向量嵌入＋餘弦刪語義重複。
  • 去污染——把測試集加進去重的比對輸入；訓練集中與測試樣本相符的一律刪除，保持測試集獨佔性。
  • 品質評估——用 LLM 評審給分（如 1–4 分）並附結構化評語；多評審＋隨機調換答案順序可降低偏誤。

2.3 Data exploration 資料探索

EN SUMMARY Before generating anything at scale, inspect the raw material: sample records, check topic coverage, text length, and anomalies. Understanding the source data guides the generation strategy and makes downstream quality problems easier to trace.
繁體對照 大規模生成之前，先檢視原始素材：抽樣閱讀、確認主題涵蓋面、文本長度與異常樣本。理解來源資料能引導生成策略，也讓後續品質問題更容易追蹤。

2.4 Data generation 資料生成

EN SUMMARY Starting from seed instructions drawn from real content, an LLM generates new instruction–answer pairs. Good prompts require instructions to be self-contained (no references to "the context" or "the original text"), answers to imitate the original author's style, and structured JSON output for reliable parsing.
繁體對照 從真實內容取出的種子指令出發，請 LLM 生成新的指令—答案配對。提示詞的關鍵要求：指令必須自足（不得出現「上下文」「原文」等指涉）、答案模仿原作者文風、以結構化 JSON 輸出方便解析。

2.5 Data augmentation 資料增強

EN SUMMARY To add difficulty and diversity, Evol-Instruct-style prompting rewrites instructions along two axes: evolution in-depth (add constraints, add reasoning steps, make the task harder) and evolution in-breadth (generate rare, varied instructions in the same domain). The augmented data must go back through the curation pipeline — synthetic data tends to copy the model's biases.
繁體對照 為增加難度與多樣性，可用 Evol-Instruct 式提示改寫指令，兩個方向：縱向演化（加限制、加推理步驟、加難）與橫向演化（在同領域生成稀有、多樣的新指令）。增強後的資料必須重新跑策展流程——合成資料容易複製模型的偏誤。

3Creating Our Own Instruction Dataset 自建資料集（實作）

EN SUMMARY The hands-on walkthrough builds the real pipeline behind the llmtwin dataset:
  • Crawl your own articles (Medium, GitHub, LinkedIn, custom sources) with crawler classes storing raw content in a data warehouse.
  • ETL step: clean the articles (special characters, whitespace, encoding) and chunk them into pieces of roughly 1,000–2,000 characters.
  • Generate instruction–answer pairs per chunk with GPT-4o mini: system + user prompts, JSON-mode output, self-contained instructions, author-style answers.
  • Orchestrate it as one main function and run it over the whole dataset, yielding ≈3,335 pairs.
  • Push the dataset to the Hugging Face Hub and review samples manually in the dataset viewer.
Code lives in the book's repo (llm_engineering/ + steps/generate_datasets/); your local copy is under repo/.
繁體對照 實作篇打造 llmtwin 資料集背後的真實管線：
  • 用爬蟲類別抓自己的文章（Medium、GitHub、LinkedIn、自訂來源），原始內容存入資料倉儲。
  • ETL 步驟：清洗文章（特殊字元、空白、編碼），切成約 1,000–2,000 字元的區塊。
  • 每個區塊用 GPT-4o mini 產生指令—答案配對：system＋user 提示、JSON 模式輸出、指令自足、答案模仿作者文風。
  • 用一個 main 函式串起整條管線，對全部資料執行，得到約 3,335 組配對。
  • 上傳 Hugging Face Hub，在資料集檢視器人工抽查。
程式碼在原書 repo（llm_engineering/ ＋ steps/generate_datasets/）；本機副本在 repo/。

4Exploring SFT and Its Techniques 探索 SFT 與其技術

4.1 When to fine-tune 該不該微調

EN SUMMARY Start with prompt engineering, not fine-tuning: few-shot prompting and RAG solve many problems on open-weight or closed models, while also building an evaluation pipeline measuring accuracy, cost, and latency. Move to SFT only when results miss requirements and enough data exists. Fine-tuning brings control ("know your data") and customizability (a unique model) and enables diverse interactions beyond a plain chatbot. But it has limits: SFT refocuses knowledge already in the base weights — distant knowledge (e.g. an unknown language) is hard to learn, fine-tuning on new knowledge can increase hallucinations, and SFT risks catastrophic forgetting of base-model abilities.
繁體對照 先從提示工程開始，別急著微調：few-shot 與 RAG 能在開放或閉源模型上解決許多問題，同時建立衡量準確率、成本、延遲的評估管線。等結果不符需求、且資料量足夠時，才進入 SFT。微調帶來控制權（「了解自己的資料」）與客製化（模型獨一無二），也能做出聊天機器人以外的多樣應用。但它有限制：SFT 是重新調校基座權重裡已有的知識——距離太遠的知識（如陌生語言）難以學會；用微調灌新知識可能加重幻覺；SFT 也有把基座能力「災難性遺忘」的風險。

4.2 Instruction dataset formats 指令資料集格式

EN SUMMARY Each sample is typically a JSON dictionary. Common storage formats: Alpaca (instruction + optional input + output — single-turn), ShareGPT and OpenAI (a conversations list of messages — multi-turn, arbitrarily long dialogs), OASST, and raw text (which is effectively continual pre-training). The choice between single-turn and multi-turn shapes storage and depends on the end use case; the book's llmtwin dataset uses the Alpaca format.
繁體對照 每筆樣本通常是一個 JSON 字典。常見格式：Alpaca（instruction ＋選填 input ＋ output——單輪）、ShareGPT 與 OpenAI（conversations 訊息清單——多輪、對話長度不限）、OASST，以及原始文本（等於持續預訓練）。單輪／多輪的選擇影響儲存方式，取決於最終用途；書中的 llmtwin 資料集採 Alpaca 格式。

4.3 Chat templates 聊天模板

EN SUMMARY After parsing the storage format, pairs are wrapped in a chat template — a unified structure with special tokens marking message boundaries and roles (e.g. ChatML's <|im_start|> / <|im_end|>). Base models have no template, so any template works when fine-tuning one; fine-tuning an instruct model (not recommended) requires reusing its own template or performance degrades. At inference you can't provide the answer: you feed the system + user parts and append the assistant header, and the fine-tuned model completes the reply — this is how instruction-following emerges.
繁體對照 解析完儲存格式後，配對要包進聊天模板——用特殊 token 標出訊息邊界與角色的統一結構（如 ChatML 的 <|im_start|>／<|im_end|>）。基座模型沒有模板，微調時可任選；微調 instruct 模型（不建議）則必須沿用其原始模板，否則效能會掉。推論時無法提供標準答案：餵入 system＋user 部分、補上 assistant 起始標記，微調過的模型就會接續回答——聽指令的能力就是這樣來的。

4.4 Parameter-efficient fine-tuning 參數高效微調（PEFT）

EN SUMMARY Full fine-tuning updates every weight. On a single GPU the memory footprint is roughly (4 bytes of weights + optimizer states + gradients + activations) × parameters — over 1 TB for a 70B model. Mitigations exist (model parallelism, gradient accumulation, 8-bit Adam, activation checkpointing) but needs stay large.

LoRA freezes the original weight matrix W and trains two small low-rank matrices A, B whose product is added to it (W' = W + B·A). The rank r is the key hyperparameter. Benefits: dramatically lower memory, faster training, task-switching by swapping adapter weights.

QLoRA quantizes the frozen base weights to 4-bit (NF4) and trains LoRA adapters on top, bringing large-model fine-tuning onto a single consumer GPU with quality close to full fine-tuning.
繁體對照 全量微調更新所有權重。單卡情境的記憶體約＝（權重 4 bytes＋優化器狀態＋梯度＋激活值）× 參數量——70B 模型超過 1 TB。有緩解手段（模型並行、梯度累積、8-bit Adam、激活值檢查點），但需求依然龐大。

LoRA 凍結原始權重矩陣 W，只訓練兩個小型低秩矩陣 A、B，其乘積加回原矩陣（W' = W + B·A）。秩 r 是關鍵超參數。好處：記憶體大幅下降、訓練更快、換任務只需換 adapter 權重。

QLoRA 把凍結的基座權重量化成 4-bit（NF4），其上只訓練 LoRA adapter，讓大模型微調跑得進單張消費級 GPU，品質接近全量微調。

4.5 Training parameters 訓練參數

EN SUMMARY Key hyperparameters and their typical ranges:
  • Learning rate & scheduler — SFT with LoRA often uses ~2e-4 with a cosine/warmup schedule; too high destabilizes, too low stalls.
  • Batch size — balance speed vs memory; gradient accumulation simulates larger batches.
  • Max sequence length & packing — set from your sample lengths; packing concatenates short samples to avoid padding waste.
  • Epochs — typically 1–10 (2–5 common); too few underfits, too many overfits — monitor validation and stop early.
  • Optimizers — AdamW is standard; 8-bit/paged variants cut optimizer memory; prefer full adamw_torch when quality is the priority.
  • Weight decay — ~0.01–0.1 (0.01 a common start); too high impedes learning.
  • Gradient checkpointing — trades recomputation for memory on long sequences.
繁體對照 關鍵超參數與常見範圍：
  • 學習率與排程——LoRA 的 SFT 常用約 2e-4，配 cosine／warmup 排程；太大不穩、太小卡住。
  • 批次大小——在速度與記憶體間取捨；梯度累積可模擬更大批次。
  • 最大序列長度與 packing——依樣本長度設定；packing 把短樣本串接，減少 padding 浪費。
  • 訓練輪數——常見 1–10 輪（2–5 居多）；太少欠擬合、太多過擬合——盯驗證集、早停。
  • 優化器——AdamW 是標準；8-bit／paged 版省優化器記憶體；品質優先時用完整版 adamw_torch。
  • 權重衰減——約 0.01–0.1（0.01 是常見起點）；太大會妨礙學習。
  • 梯度檢查點——用重算換記憶體，適合長序列。

5Fine-Tuning in Practice 微調實作

EN SUMMARY The practical run fine-tunes Llama 3.1 8B with Unsloth + TRL:
  • Load the model via FastLanguageModel (4-bit quantization, max_seq_length = 2048).
  • LoRA config: rank r = 32 (large enough for solid quality), α = 32, targeting attention + MLP projections.
  • Data: merge llmtwin with the first 10,000 samples of mlabonne/FineTome-Alpaca-100k; format with the Alpaca template and append the EOS token to every sample; split 95% train / 5% test.
  • Train with SFTTrainer (packing on, ~50 minutes on an A100).
  • Test inference with FastLanguageModel.for_inference() and a quick prompt — sanity check, not a real evaluation.
  • Save merged 16-bit weights locally and/or push to the Hugging Face Hub.
繁體對照 實作以 Unsloth ＋ TRL 微調 Llama 3.1 8B：
  • 用 FastLanguageModel 載入模型（4-bit 量化、max_seq_length = 2048）。
  • LoRA 設定：秩 r = 32（足以達到好品質）、α = 32，套用到注意力與 MLP 投影層。
  • 資料：llmtwin 合併 mlabonne/FineTome-Alpaca-100k 前 10,000 筆；用 Alpaca 模板格式化、每筆結尾加 EOS token；切 95% 訓練／5% 測試。
  • 用 SFTTrainer 訓練（packing 開啟，A100 上約 50 分鐘）。
  • 用 FastLanguageModel.for_inference() 測一句提示——快速健檢，不是正式評估。
  • 合併後以 16-bit 存檔，並／或上傳 Hugging Face Hub。

6Summary 總結

EN SUMMARY The chapter covered LLM fine-tuning in theory and practice: the instruction-data pipeline from curation to augmentation, where each stage (quality assessment, generation, enhancement) can be tuned and adapted to your use case. It applied the framework to real data from Chapter 3, converting raw text into instruction–answer pairs with an LLM. It then examined SFT itself: advantages and limits, dataset storage formats with chat templates, and the three main techniques — full fine-tuning, LoRA, QLoRA — compared by memory, efficiency, and output quality. It closed by fine-tuning Llama 3.1 8B on the custom dataset. Next chapter: preference alignment (DPO) to create a new TwinLlama-3.1-8B with chosen/rejected answer pairs.
繁體對照 本章理論與實作並重：從策展到增強的指令資料管線，每個階段（品質評估、生成、增強）都可調整、按用例取捨。接著把框架套在第 3 章的真實資料上，用 LLM 把原始文本轉成指令—答案配對。然後檢視 SFT 本身：優勢與限制、資料儲存格式與聊天模板、三大技術——全量微調、LoRA、QLoRA——依記憶體、效率、輸出品質比較。最後以自建資料集微調 Llama 3.1 8B 作結。下一章：偏好對齊（DPO），用「選中／被拒」答案對打造新版 TwinLlama-3.1-8B。
